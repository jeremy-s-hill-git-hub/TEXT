# 文档提交规范 v1.1

> 状态：正式版。生效后旧格式立即废除。本文由 AI 模型辅助整理与生成。

## 1. 格式

标准格式：

```text
<type>(<scope>): <subject>

Changes:
- content1
- content2

Files:
- filename1.abc
- filename2.efg

<paragraph1>

<traditional_year>
<traditional_month&traditional_day&solar_term>
Signed-off-by: <姓名> <邮箱>
```

内容或文件较少时用紧凑格式，`Changes` 和 `Files` 各压一行：

```text
docs(notes): 补充背景注释

Changes: 补充人物背景; 修正时间线
Files: notes.txt; timeline.md

补充人物背景，并修正时间线中的一处矛盾。

黄帝四七二一年
腊月初十 · 小寒后两天
Signed-off-by: 张三 <zhangsan@example.com>
```

无明确范围时省略 `(scope)`：

```text
chore: 移除过时附录

Changes: 移除旧版附录
Files: appendix_old.md

黄帝四七二一年
腊月十八 · 立春前三天
Signed-off-by: 张三 <zhangsan@example.com>
```

## 2. 字段

`type` 必填，小写，取 `feat / fix / docs / style / refactor / chore / revert`，无法归类用 `chore`。`feat(chapter1): 新增第一章初稿`、`fix(notes): 修正时间线矛盾`、`docs(readme): 补充安装说明` 都是常见写法。

`scope` 可选，表示文档范围，如 `chapter1`、`notes`、`appendix`，不含空格、括号、冒号。

`subject` 必填，中文祈使句，不加句号，建议不超过 30 字，header 整行不超过 72 字符。

`Changes` 必填，列出主要改动，列表或 `Changes: a; b` 均可。`Files` 必填，含后缀名，不写绝对路径，列表或 `Files: a; b` 均可。文件名或内容含分号时，改用列表格式。

正文可选，放 `Files` 后，空一行，用于说明背景、原因、影响，不要复述 `Changes` 和 `Files`。

页脚三行连续，不空行：第 1 行黄帝纪年/中元，第 2 行农历月日 + 节气或相对描述，第 3 行 DCO 签名。多签名时，传统两行在前，多个 `Signed-off-by` 连续在后：

```text
黄帝四七二一年
腊月初八 · 小寒
Signed-off-by: 张三 <zhangsan@example.com>
Signed-off-by: 李四 <lisi@example.com>
```

## 3. 节气标注

远程合并/推送时，若当天为节气，应在节气当天提交，这是强制规范，因为合并分支只应在节气当天进行。本地提交不强制，可有多条本地记录，但建议遵循。非节气日提交时，页脚第 2 行写最近的“节”及相差天数。

十二节：立春、惊蛰、清明、立夏、芒种、小暑、立秋、白露、寒露、立冬、大雪、小寒。  
十二气：雨水、春分、谷雨、小满、夏至、大暑、处暑、秋分、霜降、小雪、冬至、大寒。  
顺序为节 → 气 → 节 → 气。气只作分界，不作计数基准。

```text
节A → 气B → 节C
```

在 A 到 B 之间写 `A后X天`，在 B 到 C 之间写 `C前X天`，当天为节或气则直接写名称。天数用汉字或阿拉伯数字均可。

```text
腊月初八 · 小寒
腊月初十 · 小寒后两天
腊月十五 · 大寒
腊月十八 · 立春前3天
正月廿九 · 惊蛰
二月初五 · 惊蛰后五天
```

## 4. DCO

格式固定为 `Signed-off-by: 姓名 <邮箱>`，必须与 Git 提交的 `Author` 一致。可用真实邮箱、项目专用邮箱或 GitHub 匿名邮箱。`git commit -s` 可自动追加。个人内部文档也可使用，但法律效力有限。

## 5. 格式规则

header 后必须空一行。`Files` 与正文、正文与页脚之间必须空一行。页脚三行连续，不空行。使用 UTF-8。禁止 header 列文件名、写多个主要目标、使用绝对路径、用 Markdown 代码块包裹、末尾加句号。

## 6. 提交本规范文档

```text
feat(docs): 新增文档提交规范 v1.1

Changes: 定义提交类型、正文、页脚、DCO 与节气标注
Files: commit-spec.md

黄帝四七二三年
八月廿六 · 寒露前2天
Signed-off-by: 姓名 <邮箱>
```

本地临时提交可暂省传统两行与 DCO，推送前必须补齐：

```text
feat(docs): 新增文档提交规范 v1.1

Changes: 定义提交规范
Files: commit-spec.md
```

## 7. 提交简洁原则

可省略：规范正文、正文段落、`scope`、`Changes`/`Files` 列表可压成紧凑格式、多段正文、本地临时提交的传统两行与 DCO、解释性文字。  
不可省略：`type`、`subject`、`Changes`、`Files`、传统纪年、农历月日+节气/相对、DCO 签名、必要空行。

最简模板：

```text
<type>(<scope>): <subject>

Changes: <内容1>; <内容2>
Files: <文件1>; <文件2>

<traditional_year>
<traditional_month&day · 节气或相对>
Signed-off-by: <姓名> <邮箱>
```

无 scope 时去掉 `(scope)`。

## 8. 旧格式处理

旧格式废除。旧 `Update/Create/Delete` 映射为：`update` 用 `docs` 或 `feat`，`create` 用 `feat`，`delete` 用 `chore` 或 `revert`。文件名移入 `Files`，内容移入 `Changes`，`significant` 改为 `Signed-off-by`，传统纪年与日期移入页脚两行。

## 9. 可选校验

接入自动化校验时可用：header 正则 `^(feat|fix|docs|style|refactor|chore|revert)(\([^)]+\))?: .+$`，header 不超过 72 字符，`Changes` 与 `Files` 必填，`Files` 每项含后缀名，禁止绝对路径和空 subject，DCO 用 `^Signed-off-by: .+ <.+>$` 校验。传统两行不做机器校验。

本规范自确认之日起执行。
